02 / 这本说明书里有什么

记住你说过什么，
也分清哪些只是理解。

从角色、经历、价值、目标、偏好、决策、行为和约束八个入口了解你。无需填满所有栏目。

A / 原始依据

发生过什么

保存必要的表达或事件，并注明什么时候发生、信息来自哪里。

“最近在考虑换工作。”一条有来源、有时间的表达。
B / 个人理解

这说明什么

区分具体信息、当前状态、AI 解释与反复出现的模式，并关联依据。

“正在评估，尚未决定。”这是当前状态；解释会另外标明。
C / 轻量摘要

先了解重点

只选你允许长期使用的稳定信息。每次载入前先检查是否仍然适用。

“沟通时喜欢先看结论。”临时离职想法通过按需查询提供。
原始依据 → 个人理解 → 轻量摘要　·　前面的信息被纠正，后面的内容也要重新检查。
03 / 背后怎样分工

AI 负责理解，
本地工具负责把规则执行好。

可以把它想成一个小团队：接待员负责与你沟通，档案管理员负责按规矩查找和保存。

入口 / ADAPTERS

你使用的 AI

将你的请求接进来，把获准内容作为资料使用。不同平台需要遵守相同的加载约定。

像一个接待窗口V1 接入一个本地宿主；跨平台后续扩展。
沟通 / SKILLS

与你一起整理

提问、整理候选、解释建议，展示要保存或修改什么。由你选择确认哪些内容。

像一位访谈助手三个工作流：建立、查找、更新。
保管 / MEMORY

你的个人档案

记录默认放在本机的独立目录，也可由你另选。本地工具先检查权限，再查找；关联修改一起保存，失败时恢复。

像一位档案管理员每条记录独立保存，原始依据可追溯。
共同规则 / CORE怎样表示信息 · 怎样确认 · 什么时候有效 · 谁可以使用 · 怎样更正和忘记

这是 WhoAmI OS 的四层分工。本地读写工具属于 Memory；它负责执行检查，AI 负责提出和解释候选。首个 Codex 本地接入已落地；其他宿主接入仍在规划。

01 / 保存

02 / 权限

03 / 纠错
改源头，也检查后续理解

04 / 摘要
先验证，再交给 AI

05 / 读取
少量、相关，同时说明遗漏

06 / 验证
既看可靠，也看有没有帮助

想再深入一点：本地最小版 OS 包含什么？

四层为 Core（规则）、Memory（个人记录与本地读写工具）、Skills（访谈和操作流程）、Adapters（宿主接入约定）。三个工作流为 Initialize / Recall / Update；本地操作边界为 open / recall / prepare / apply / recover。

个人目录以 YAML 保存结构化记录，Markdown 是可重建的摘要。macOS 默认保存在“资源库 / Application Support / WhoAmI / personal-memory”，Windows 默认保存在当前用户的“AppData / Local / WhoAmI / personal-memory”，也可另选；Git 版本追踪可选。本地最小版暂不包含数据库、向量库、产品 Web UI、后台监听或自动跨平台同步。这份 HTML 仅作说明。

如果保存时出错，或者我手动编辑了文件呢？

设计要求保存前绑定确认内容与文件版本，关联修改在同一受控过程中完成。中断时依据日志恢复；发现外部修改时停止覆盖，重新展示差异。手工编辑后会停止受控写入；重新接纳这些改动的流程仍在后续范围。

本地工具已有中断恢复测试；完整可靠性仍需进一步验收。其他直接访问目录的程序不受这套流程控制。

它会替我定义“我是什么样的人”吗？

一次表达只说明当下，未知不补猜。AI 解释始终注明来源和不确定性；即使你确认保存，也不会自动变成客观事实。反复模式需要独立事件、时间与例外支持，并再次请你确认。你可以纠正这些理解，也可以拒绝保存。
